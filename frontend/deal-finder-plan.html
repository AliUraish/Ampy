TL;DR

Build: a fresh, standalone Deal Finder app that lifts three files from Hagglr (the Craigslist fetcher, the concurrency helper, the locations list) and nothing else. Pick a city + category, the agent scans live Craigslist, values each listing (Pixtral on the photo + Craigslist comps), checks demand, and streams back the 5-10 underpriced listings with its reasoning. No buying, no payments, no messaging. Agent brain is Mistral end to end.

Steps 3, 4, 5 run per listing inside one mapWithConcurrency(listings, 4, scoreOne). Each finished listing emits an SSE event immediately, so the UI fills in live instead of waiting for the whole batch. That's what makes the demo feel like an agent working rather than a spinner.

Cheap pre-filter (saves Mistral calls)

Before calling Mistral, drop listings with price === null, and anything priced above the comps median (it can't be underpriced). On a 60-listing scan this typically leaves 20-25 candidates → 25 Pixtral calls, ~30-40 s total at 4-way concurrency. Fine for a demo.

Buckets (drive the UI ring color)

≥ 75 Strong deal 50-74 Maybe < 50 Pass. Feed shows only ≥ 50 by default, toggle to show all.

// lib/dealScore.js  (pure, unit-testable, no I/O)
function scoreDeal({ price, compsMedian, compsN, mistralEstimate, demand, hasPhoto, descLen }) {
  const fairValue = 0.6 * compsMedian + 0.4 * mistralEstimate;
  const marginRaw = Math.max(-1, Math.min(2, (fairValue - price - 15) / price));
  const marginN = (marginRaw + 1) / 3;
  const agreement = 1 - Math.min(Math.abs(compsMedian - mistralEstimate) / compsMedian, 1);
  const confidence = 0.4 * Math.min(compsN / 8, 1) + 0.3 * agreement + 0.2 * (hasPhoto ? 1 : 0) + 0.1 * Math.min(descLen / 300, 1);
  let score = Math.round(100 * (0.5 * marginN + 0.3 * demand + 0.2 * confidence));
  const flags = [];
  if (price < 0.2 * fairValue) { flags.push("too_good"); score = Math.min(score, 40); }
  return { fairValue, margin: marginRaw, marginN, demand, confidence, score, flags };
}

Illustrative weights. Tune them against the 10 hand-labeled listings from the assignment; if the top 3 by score match your gut, ship it.

// lib/mistral.js
const BASE = "https://api.mistral.ai/v1/chat/completions";
async function chatJSON({ model, messages, maxTokens = 600 }) {
  const r = await fetch(BASE, {
    method: "POST",
    headers: { Authorization: `Bearer ${process.env.MISTRAL_API_KEY}`, "Content-Type": "application/json" },
    body: JSON.stringify({ model, messages, response_format: { type: "json_object" }, max_tokens: maxTokens, temperature: 0.2 }),
  });
  if (!r.ok) throw new Error(`mistral ${r.status}: ${await r.text()}`);
  const data = await r.json();
  return JSON.parse(data.choices[0].message.content);
}
// vision message content: [{type:"text", text: prompt}, {type:"image_url", image_url: photoUrl}]

No SDK needed; plain fetch like Hagglr does for Telegram. Add MISTRAL_API_KEY to .env.example. Verify model IDs against Mistral's current model list on day 1; names drift.

Valuation prompt (verbatim starting point)

You are a used-goods appraiser for {city}. Identify the item in the photo and text.
Listing title: {title}
Description: {description}
Asking price: ${price}
Other listings for "{query}" in {city} right now have a median price of ${compsMedian} (n={compsN}).
Return JSON: { "item": string, "brandModel": string|null, "condition": "new|like new|excellent|good|fair|poor",
  "estimatedResaleUsd": number, "redFlags": string[], "reasoning": string (max 60 words, concrete, mention what you saw in the photo) }
Be skeptical: stock photos, missing photos, vague text, or prices far below market are red flags.

Demand signal (the Google Trends question)

There is no official Google Trends API. The practical hackathon answer is a 20-line Python sidecar using pytrends, called from Node via child_process, cached per keyword for the whole session. It gets rate-limited (429) after a few dozen calls, so: cache hard, and fall back without drama.

Do we have a brand/model from Pixtral?
Yes → pytrends interest_over_time("trek fx 3", geo="US-CA", 90d) → mean of last 4 weeks ÷ peak → 0..1
429 / timeout / empty → use category fallback table
No → category fallback table (bikes .70, electronics .80, instruments .60, furniture .45, appliances .50)

Surface the source in the UI: Trends vs category baseline. Same honesty pattern as Hagglr's floorPriceSource. Optional upgrade if time allows: ask Mistral for a 1-5 "how fast does this resell locally" rating and blend it; it's a judgment, label it as one.

Visual system (keep it tight, borrow Hagglr's style.css tokens)

Dark background, one accent, green/amber/red only for score. Monospace in the console, sans everywhere else. No cards-inside-cards. Ring = score, big number = profit delta in dollars (people feel dollars, not percentages). Mobile is not a target.
